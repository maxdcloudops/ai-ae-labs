# ДЗ 2 — типізований інструмент курсу валют (базовий шлях)

**Прогін: 27–28.09.2026.** Go 1.27.1 · `adk/v2 v2.4.0` · дані — **живий API НБУ**, без ключа.

Один файл, [`main.go`](main.go): контракт, валідація, провайдер і проводка в агента.

## Як запустити

```bash
cd submission-min/week1/day2

go run . quote USD UAH 3       # прямий виклик інструмента — БЕЗ моделі й ключа
go run . console               # діалог з агентом (потрібен ключ або endpoint)
```

## Контракт: три рівні, масив, enum

```
RateOutput                      ← рівень 1
├── source   Source             ← рівень 2
│   └── kind SourceKind         ← ENUM: "api" | "mock"
└── history  []HistoricalPoint  ← рівень 2, МАСИВ
    └── [n].source Source       ← рівень 3
        └── kind SourceKind     ← ENUM
```

Схема генерується автоматично з Go-структур — жодного рукописного JSON Schema.

Кожна точка історії несе **власний** `source`, а не успадковує загальний: числа
можуть приходити з різних джерел, і один `source` на всю відповідь брехав би про
половину з них — саме в полі, яке існує, щоб числу можна було довіряти.

### Реальний вихід (`go run . quote USD UAH 3`, живий НБУ)

```json
{
  "base": "USD", "target": "UAH",
  "rate": 44.8414,
  "as_of": "2026-09-28",
  "source": { "kind": "api", "name": "nbu" },
  "history": [
    { "date": "2026-09-24", "rate": 44.8571, "source": { "kind": "api", "name": "nbu" } },
    { "date": "2026-09-25", "rate": 44.9729, "source": { "kind": "api", "name": "nbu" } },
    { "date": "2026-09-26", "rate": 44.9729, "source": { "kind": "api", "name": "nbu" } }
  ]
}
```

Днів у відповіді буває менше, ніж запитано: у вихідні НБУ курсу **не публікує**,
і такі дні пропускаються. Заповнити їх учорашнім числом означало б вигадати
котирування, якого не було.

## Валідація: валідний JSON ≠ валідний виклик

`{"base":"US1","target":"UAH"}` розбирається `json.Unmarshal` **без помилки** —
схема довела форму. Виклик усе одно не має права виконатись, і помилка мусить
назвати конкретне значення, інакше моделі нема що виправляти.

Реальні прогони ([`results/validation.txt`](results/validation.txt)):

```console
$ go run . quote US1 UAH
field "base": invalid currency code: "US1" must be three LATIN letters (ISO 4217)

$ go run . quote USDD UAH
field "base": invalid currency code: "USDD" must be three letters (ISO 4217)

$ go run . quote XQZ UAH
unknown currency code: XQZ is not published by the NBU

$ go run . quote usd uah
{ "base": "USD", ... }          # регістр нормалізується: це та сама валюта
```

Зверніть увагу на різницю між другим і третім рядком. `USDD` відхиляє
**валідація форми** — мережі не потрібно. А `XQZ` має бездоганну форму: три
латинські літери. Що такої валюти не існує, знає тільки **джерело**. Це два
різні рівні межі, і плутати їх дорого: помилка рівня домену, подана як «bad
request», відправить модель виправляти тип замість значення.

## Три діалоги — і чому їх тут немає

**Ключа провайдера в мене немає.** На локальному mock-бекенді агент tool-call-ів
не робить узагалі — мок повертає заготовлений текст незалежно від запиту. Тож
три діалоги з вимоги завдання я в базовому варіанті показати не можу й не
вигадуватиму їх.

Що працює й перевірено без ключа — **сам інструмент**: контракт, валідація,
крос-курс, історія, походження (див. вище, дані живі).

З ключем ті самі діалоги дають:

```bash
echo "Який курс долара до гривні? Покажи ще 3 дні." | go run . console
echo "Скільки коштує USDD у гривнях?"               | go run . console
echo "Порівняй курс євро та фунта."                 | go run . console
```

Повні транскрипти з реальними tool-call-ами (перший виклик відхилено, другий
пройшов) є в розширеному варіанті:
[`submission/week1/day2/results/dialogues.txt`](../../../submission/week1/day2/results/dialogues.txt) —
там модель скриптована, тому діалоги вийшли детермінованими й без ключа.

## Fail path

Три різні відмови, і кожна каже користувачу різне:

| Ситуація | Помилка | Що це означає |
|---|---|---|
| `US1` | `invalid currency code` | виправ **значення** — форма неправильна |
| `XQZ` | `unknown currency code` | такої валюти немає, «пізніше» не допоможе |
| НБУ недоступний | `rate provider unavailable` | спробуй пізніше |

Головне спільне: жодна з них не повертає число. Агент, який на збій апстріму
відповідає курсом, гірший за агента, який чесно падає — бо його помилку ніхто
не помітить.

## Prompt vs Contract

Інструкція агента просить завжди викликати інструмент і не вигадувати курс.
Опис інструмента (`toolDescription`) тут важить навіть більше: **модель не читає
ваш код, вона читає цей рядок** — саме за ним вона вирішує, викликати чи
відповісти з пам'яті.

Але інструкція — це прохання. Вона тримається на тому, що модель послухається,
і слабшає з кожною тисячею токенів контексту. Тест, який доводить, що вона
виконуватиметься завжди, показати неможливо.

JSON Schema, валідація й типізований результат — це властивості системи. `US1`
не дійде до НБУ не тому, що модель слухняна, а тому, що `normalizeCode` повертає
помилку. Це покривається тестом і не залежить ні від моделі, ні від контексту.

Правило: **інструкція визначає, що агент спробує зробити; контракт визначає, що
системі дозволено зробити.** Перше оптимізують, друге доводять.

## MCP пізніше

Зараз `get_exchange_rate` — Go-функція в тому самому процесі, і межу забезпечує
компілятор. MCP виносить ту саму межу за межі процесу: `tools/list` віддає
**`inputSchema`** і **`outputSchema`**, `tools/call` передає аргументи. Правило
не змінюється, а посилюється: **MCP-сервер валідує вхід ДО виконання й санітизує
вихід ПІСЛЯ**. І окремо: **A2A — це не інша назва MCP**: MCP це agent ↔ tool,
A2A — agent ↔ agent.

## Week 2 bridge

`RateInput`/`RateOutput` уже є `InputSchema`/`OutputSchema` — просто зараз їх
читає `functiontool`. У Тижні 2 ті самі типи стають контрактом вузла графа:

```go
rateNode := workflow.Node{
    Name:         "fetch_rate",
    InputSchema:  RateInput{},    // той самий тип
    OutputSchema: RateOutput{},   // той самий тип
    Run:          Convert,
}
graph := workflow.Sequential(parseIntentNode, rateNode, formatAnswerNode)
```

Переноситься без змін головне: **вузол з'єднується з наступним по схемі, а не по
тексту**. Саме тому вкладений `RateOutput` із `source.kind` вартий зусиль
сьогодні — наступний вузол зможе розгалузитися на `source.kind == "mock"` без
парсингу рядків.
