## Мануальний цикл — увесь агент у двадцяти рядках

```go
for i := 1; ; i++ {
    if i > b.MaxIterations {                        // ліміт ПЕРЕД викликом
        return "", trace, fmt.Errorf("вичерпано ліміт %d ітерацій: %w", b.MaxIterations, ErrMaxIterations)
    }
    step, err := p.NextStep(ctx, history)           // Thought
    if step.Final {
        return step.Answer, trace, nil
    }
    obs := make([]react.Observation, 0, len(step.Calls))
    for _, call := range step.Calls {
        obs = append(obs, reg.Invoke(ctx, call))    // Action → Observation
    }
    history = history.Append(step, obs)             // без цього — нескінченний цикл
}
```

Жодної магії всередині немає. Планувальник каже, що робити; реєстр це виконує;
історія несе результат у наступний крок. Коли фреймворк «робить агента», він
робить рівно це.

Три рішення, які виглядають дрібницями й такими не є:

**Ліміт перевіряється перед викликом планувальника.** Якщо після — остання
ітерація встигає заплатити за крок, який ми вже вирішили не робити.

**Порядок спостережень = порядок викликів**, і кожне несе `CallID` свого
виклику. Це кореляція one-or-many: модель може попросити три інструменти одним
кроком, і сплутати відповіді не можна. Закріплено `TestRunKeepsObservationsInCallOrder`.

**`history.Append` обов'язковий.** Без нього наступний крок не бачить
результату й повторює той самий виклик — найчастіший спосіб отримати цикл,
який ніколи не збігається.

**Trace повертається і разом із помилкою.** О третій ночі питання звучить
«де воно застрягло», і відповідає на нього слід, а не текст помилки.

## Графова версія — той самий цикл як вузол

```go
step := workflow.NewFunctionNode("plan_step", …)          // крок = вузол
loop := workflow.NewDynamicNode[string, string]("react_loop",
    func(ctx agent.Context, task string, _ func(*session.Event) error) (string, error) {
        for i := 1; ; i++ {
            if i > b.MaxIterations { … ErrMaxIterations }
            r, err := workflow.RunNode[StepResult](ctx, step, i)   // крок через runtime
            if r.Final { return last.Answer, nil }
            …
        }
    }, workflow.NodeConfig{})
```

Той самий текст помилки й **той самий сентинел** `ErrMaxIterations`: тести
перевіряють обидві версії через `errors.Is`, і розбіжність тут означала б, що
«еквівалентні» реалізації відрізняються рівно в місці, яке ловить збій.

## Руками проти runtime: що насправді змінюється

| | Мануальний `for` | Динамічний вузол |
|---|---|---|
| Рядків на цикл | ~20 | ~25 + вузол |
| Видимість ітерацій | треба інструментувати самому | кожна ітерація — подія в event log |
| Стан між кроками | локальна змінна `history` | `history` + `last` поза вузлами |
| Відлагодження | звичайний стек і `trace` | стек + граф, помилка загорнута в ітерацію |
| Зупинка | `return` | `return` з динамічного вузла |

**Головна відмінність не в коді, а в спостережуваності.** Мануальний цикл
прозорий для розробника і німий для системи: щоб побачити ітерації збоку,
треба дописати логування. Графовий навпаки — кожен крок сам пише подію, і
`event log` показує траєкторію без жодного рядка логування.

**Ціна цього — прихований стан.** `StepResult` їде в лог і має бути
серіалізовним, тож повний `react.Step` (із `Calls` і `genai.Content` усередині)
в нього не покладеш. Крок пише результат у змінну `last`, цикл читає її
звідти — зв'язність між вузлами, якої в мануальній версії немає.

Практичний наслідок: **один агент = один прогін**. `workflowagent` не ділить
`last` і `history` між паралельними інвокаціями, тож для кількох одночасних
запитів потрібен агент на запит. У мануальній версії це не питання взагалі —
стан локальний для виклику `Run`.

**Коли що брати.** Мануальний — коли цикл простий, а відлагоджувати його буде
той, хто його написав. Графовий — коли ітерації треба показувати комплаєнсу,
або коли крок складніший за один виклик планувальника і сам хоче бути
підграфом. На цій задачі різниця в користі невелика; вона з'явиться в ДЗ 8,
де крок почне падати й повторюватися.

## Ліміт ітерацій

Обидві версії зупиняються з `ErrMaxIterations`, і обидві перевіряються через
`errors.Is`:

| Тест | Версія |
|---|---|
| `TestRunStopsAtIterationLimit` | мануальна |
| `TestADKAgentStopsAtTheStepCap` | графова |

Нуль у `Budget.MaxIterations` не означає «без обмежень» — `Normalized()`
підставляє `DefaultMaxIterations = 10`. «Необмежено» не є валідним
налаштуванням для циклу, який викликає платну модель.
